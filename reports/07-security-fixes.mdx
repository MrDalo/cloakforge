## Cloudflare — recommendation

- **Don't proxy (orange cloud) Cloudflare in front of Vercel.** Vercel advises against it: it hides real client IPs from the Vercel Firewall/WAF and Bot Protection (your rate limits would see Cloudflare IPs), adds latency and causes cache/TLS issues.
- **Worth using:** Cloudflare **Turnstile** (free CAPTCHA) on IPFS upload / coupon validate if abuse appears; **Email Routing** (free) for `help@`, `privacy@`, `security@`; DNS in **DNS-only (grey cloud)** mode if you prefer Cloudflare DNS (Vercel DNS is also fine).

## Known trade-offs / follow-ups

- **Coupon griefing:** a use is reserved when a tx is built, so someone who knows a public code can exhaust it by building txs without signing. WAF limits reduce this; a stronger design counts only confirmed on-chain memos (via `getSignaturesForAddress` on the fee wallet).
- **Fallback fees** (used only when Contentful is down): token-creator 0.19, burn 0.009, multisender 0.001/recipient, freeze/unfreeze 0.01/wallet, revoke mint/freeze 0.1, revoke-metadata & update-metadata 0.05 SOL — revoke-metadata UI shows 0.1, confirm the intended value.
- **Token-2022 transfer-hook mints** fail in the multisender (`TransferChecked` without extra accounts).
- **Not yet fixed (next rounds):** Token Auditor mock data (WEB3-03), MetadataPointer authority (WEB3-04), liquidity tool fee + slippage (WEB3-05/06), client-side tx verification before signing (WEB3-07), CI hardening (M2/M3), legal must-fixes (report 04).
- Next 16.4 warns that `partialPrefetching` should be set explicitly alongside `cacheComponents`.
